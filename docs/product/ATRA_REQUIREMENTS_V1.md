# Atra 要件定義書 v1

**提出日:** 2026-09-15
**分類:** PROPOSED PRODUCT DIRECTION（提案）。`PRODUCT_STATE.md` はこの文書では更新しない。
**前提:** `docs/archive/v0/` の WorkUnit OS は凍結済み。本書はそこから独立した新しい方向。

この文書は1回読んで分かることを目的とする。AI に解説させる必要があるなら失敗。

---

## 用語（この文書で使う言葉は4つだけ）

| 言葉 | 意味 |
|---|---|
| **グループ** | 1つの作業のまとまり。タブ・PR・スレッド・ファイル・メモが入っている箱。 |
| **再開ブリーフ** | グループを選んだとき右に出る「前回の自分からの引き継ぎ」。 |
| **中断メモ** | 作業を止めるときに残す1行。 |
| **判断記録** | 「これはこうすると決めた」を残したもの。消えない。 |

以降、この4語以外の名前を作らない。

## 0. 対象ユーザーと課題

### 対象ユーザー

**自分たち2名（神山まるごと高専の学生）。**

- 複数のプロジェクトを同時に持っている
- 授業・MTG・移動・就寝で1日に何度も中断される
- 中断は数十分から数日まで幅がある

対象を広げない。売れるかどうかは今は二の次。自分たちが毎日使いたいものを作る。

### 課題

**中断した作業に戻るとき、毎回「何をやっていたか」を作り直している。**

情報が足りないのではない。情報は全部ある。どこにあるか、どれが今の自分に関係あるかが
思い出せない。

| | |
|---|---|
| 1回の再開にかかる時間 | 15〜30分 |
| 1日の再開回数 | 3〜5回 |
| 1日の損失 | 約1時間 |

失われているのは時間だけではない。**再開が重いので、細切れの時間に作業を始めなくなる。**

## 1. 現状の業務フロー

システムの話は出てこない。人がやっていることだけを書く。

```
① 作業中。タブ・エディタ・ターミナル・Slack が開いている
      ↓
② 中断する（授業／MTG／移動／就寝）
      ↓ ────── 数時間〜数日 ──────
③ 机に座る。再開しようとする
      ↓
④ 「何をやってたんだっけ」と思い出そうとする        ← 思い出す
      ↓
⑤ ブラウザ履歴を遡る／Slack を遡る／PR を開く      ← 探す
      ↓
⑥ 前回何を決めたか思い出せない → もう一度調べ直す    ← 調べ直す
      ↓
⑦ 散らばっていた画面を1つずつ開き直す              ← 開き直す
      ↓
⑧ ようやく手が動き始める
```

**④〜⑦で15〜30分。** ここに価値は1つも生まれていない。

判定：これを読んだ自分たちが「そうそう、これ」と言うか。言わなければこの節が間違っている。

## 2. 導入後の業務フロー ★本書の中心

Atra は **Raycast 拡張**。専用アプリを開かない。既に毎日押しているホットキーの中にいる。

画面ごとに、**何が見えて・何を押して・次に何が起きるか**を書く。
システム側の処理ではなく、椅子に座っている人の視点で書く。

---

### 画面 1 — 起動直後

**操作：** `⌥Space`（Raycast のホットキー）→ `atra` と打つ → Enter

**見えるもの：** グループの一覧。1行＝1つの作業のまとまり。

```
┌──────────────────────────────────────────────────────────────┐
│ 🔍 atra                                                       │
├──────────────────────────────────────────────────────────────┤
│  再開する                                                     │
│                                                              │
│ ▸ Atra 要件定義                          2時間前   7件        │
│     比較図を描くところで止めた                                 │
│                                                              │
│   Hopper ランキング実装                   昨日     12件       │
│     ベクトル統合の分離メモリまで書いた                          │
│                                                              │
│   学校 / 情報数学レポート                 3日前    4件        │
│     設問3が分からず放置                                       │
│                                                              │
│   採用面談の準備                          5日前    3件        │
│     日程だけ決まっている                                       │
└──────────────────────────────────────────────────────────────┘
```

1行に入っているものは4つだけ：**名前 / 最後に触った時刻 / 中断メモ / 中身の件数**。
これ以上増やさない。読む時間が増えたら負け。

**並び順：** 「今これを再開する確率が高い順」。最終更新時刻を軸に、時間帯（毎朝この作業をしている、など）で補正する。名前順でもアルファベット順でもない。

**ここで一番上に自分の作業が来ていれば、それだけで勝ち。** 探す操作が消える。

---

### 画面 2 — グループを選ぶ（まだ開かない）

**操作：** `↑` `↓` で移動するだけ。Enter はまだ押さない。

**起きること：** 右ペインに **再開ブリーフ** が出る。これが「前回の自分からの引き継ぎ」。

```
┌───────────────────────────┬──────────────────────────────────┐
│ ▸ Atra 要件定義  2時間前   │  Atra 要件定義                    │
│   Hopper ランキング  昨日  │  ─────────────────────────────    │
│   情報数学レポート  3日前  │  中断メモ                         │
│   採用面談の準備   5日前   │  「比較図を描くところで止めた」     │
│                           │                                  │
│                           │  前回決めたこと                   │
│                           │  ・非機能要件は今回書かない        │
│                           │  ・ICP は自分たち。広げない        │
│                           │  ・特化の定義は今決めない          │
│                           │                                  │
│                           │  中身（7件）                      │
│                           │  🌐 門馬さんの構成メモ             │
│                           │  🌐 Raycast API ドキュメント       │
│                           │  ⌥ PR #254 docs boundary          │
│                           │  💬 Slack / 斎藤さん 9/01          │
│                           │  📁 ~/Atra-workunitOS             │
│                           │  📄 docs/product/…V1.md           │
│                           │  📝 メモ：比較図は必ず図にする      │
│                           │                                  │
│                           │  次にやること                     │
│                           │  比較図（1と2を並べる）            │
└───────────────────────────┴──────────────────────────────────┘
```

**この画面が本体。** ここを読み終わった時点で、頭の中は中断前に戻っている。
現状フローの④⑤⑥（思い出す・探す・調べ直す）がここで消える。

「前回決めたこと」は自動生成された要約ではなく、**自分が判断記録として残したもの**。
だから信用して読み飛ばせる。

### 画面 3 — 再開する

**操作：** `Enter`

**起きること：**

1. Raycast が閉じる
2. グループの中身が一括で開く（ブラウザのタブ群、エディタ、ターミナルは該当ディレクトリで）
3. 画面が中断前の状態に戻っている

**所要時間：目標 2秒以内。** 画面 1 から数えて **`⌥Space` → `atra` → `↓` → `Enter` の4操作。**

Atra が出てくるのはここまで。以降は普通に作業する。

**操作：** グループを選んだ状態で `⌘K`

**操作：** `⌥Space` → `park` → Enter

```
┌──────────────────────────────────────────────────────────────┐

├──────────────────────────────────────────────────────────────┤
```

紐づけ先のグループは自動で推定され、違えば `↓` で選び直す。

ここを重くすると誰も使わない。**中断は5秒、再開は2秒。**

**操作：** `⌥Space` → `add` → Enter（今見ているタブが対象）

### 画面 7 — グルーピングが間違っていたとき

**操作：** 再開ブリーフの中身の行を選び、`⌘K` → 「このグループから外す」／「分割」

**起きること：** 移動するだけでなく、**「人間がここを訂正した」という事実が判断記録として残る。**
次の推薦はこれを使う。訂正が積み上がるほど画面1の並び順が当たるようになる。

グルーピングは必ず外れる。**外れたときのコストを1操作にすることが設計目標。**

```
      ↓
```

## 3. 1と2の比較

```
  現状                              導入後
  ────────────────────────          ────────────────────────
  ① 作業中                          ① 作業中
  ② 中断する                         ② ⌥Space → park → Enter     5秒
                                       ↓
  ────── 数時間〜数日 ──────         ────── 数時間〜数日 ──────

  ③ 机に座る                         ③ ⌥Space → atra
  ④ 何をやってたか思い出す    ✗
  ⑤ 履歴・Slack・PR を遡る    ✗  ──→   再開ブリーフを読む          20秒
  ⑥ 前回の判断を調べ直す      ✗
  ⑦ 画面を1つずつ開き直す     ✗  ──→   Enter で一括で開く           2秒
  ⑧ 手が動く                        ④ 手が動く

  ────────────────────────          ────────────────────────
  15〜30分                           約30秒
```

**消える手順：④ ⑤ ⑥ ⑦（✗ の4つ）。**

- ④⑤⑥（思い出す・探す・調べ直す）が消える理由 → **再開ブリーフ**
- ⑦（開き直す）が消える理由 → **一括で開く**

増える手順は②の5秒だけ。**5秒払って15〜30分を買う。**

## 4. ルール

守らないと「思い出せる」が壊れるもの。

| # | ルール | なぜ |
|---|---|---|
| 1 | **グループを確定させるのは人間。AI は候補を出すだけ。** | 勝手に分類されると、外れたときに探す場所が消える |
| 2 | **勝手に閉じない・消さない・アーカイブしない。** | 1回消されたら二度と信用されない |
| 3 | **判断記録は上書きしない。積む。** | 「前回どう決めたか」が消えると調べ直しが復活する |
| 4 | **本文は外に出さない。外に出るのはメタ情報だけ。** | 自分たちの Slack・学校の課題・採用の話が入る |
| 5 | **グルーピングが全部外れていても、検索で辿り着ける。** | 推薦が外れた日に作業が止まってはいけない |
| 6 | **中断5秒・再開2秒を超えたら機能を削る。** | 重い記録作業は必ず続かない |
| 7 | **画面1の1行に4項目以上を出さない。** | 読む時間が増えた時点で目的に反する |

## 5. 必要機能

MVP に入れるものだけ。ここに無いものは作らない。

### グループ
- 作成 / 命名 / 分割 / 統合 / アーカイブ
- 並び替え（最終更新 + 時間帯 + 訂正履歴）

### 中身
- 登録できるもの：URL、ファイルパス、リポジトリ、PR / Issue、Slack スレッド、ターミナルの作業ディレクトリ
- 追加（画面6）／ 外す（画面7）

### 記録
- 中断メモ（1行、任意）
- 判断記録（追記のみ、消えない）
- 訂正の記録（画面7で自動）

### 再開
- 再開ブリーフの生成
- 一括で開く / リンクだけ開く

### 入れないもの（今回は作らない）
- 自動実行・自動送信
- チーム共有 / 権限管理
- Web ダッシュボード
- V0 の WorkUnit / Graph / Action Field / 承認フロー

## 6. 出力形式

Atra の出力は3つだけ。

| 出力 | どこに出るか | 中身 |
|---|---|---|
| **グループ一覧** | Raycast List（画面1） | 名前 / 最終更新 / 中断メモ / 件数 |
| **再開ブリーフ** | Raycast Detail（画面2） | 中断メモ / 前回決めたこと / 中身 / 次にやること |
| **一括オープン** | OS の操作（画面3） | タブ・エディタ・ターミナルが開く |

加えて、グループはローカルに **人間が読める JSON** としても書き出せる。
Atra が動かなくなっても中身が取り出せることを保証するため。

## 7. システム構成

```
┌──────────────────────────────────────────────┐
│  Raycast（フロントは作らない・借りる）          │
│  List / Detail / Action Panel                │
└───────────────────┬──────────────────────────┘
                    │  拡張（TypeScript）
┌───────────────────▼──────────────────────────┐
│  ローカルストア（Mac の中から出ない）            │
│  グループ / 中身 / 中断メモ / 判断記録           │
└───────────────────┬──────────────────────────┘
                    │  メタ情報のみ（本文は送らない）
┌───────────────────▼──────────────────────────┐
│  Atra Core ← ここを自分たちで作る               │
│  ・グルーピング候補の生成                       │
│  ・再開順のランキング（訂正履歴で学習）           │
│  ・時間の二軸モデル                             │
│  ・判断記録の保管                               │
└──────────────────────────────────────────────┘
```

**フロントは Raycast を使う。自分たちが作るのは Atra Core。**
UI を作らない分の時間を、グルーピングの精度に全部使う。

## 8. 差別化

1. **時間を2軸で持つ。** 情報が「いつ起きたか」と「自分がいつ知ったか」を分けて記録するので、再開時に「中断した時点の自分は、どこまで知っていたか」を復元できる。
2. **人間の判断が記録として残る。** 前回決めたことも、グルーピングの訂正も、上書きされず積み上がる。
3. この2点は V0 で作った考え方を持ち込んでいる。**持ち込むのは考え方だけで、V0 の製品方向・語彙・コードは引き継がない。**

以上。3行を超えない。

## 9. 今どこまで決まっていて、どこを決めていないか

**決まっている：**
- 対象ユーザーは自分たち2名。広げない
- 作るのは情報のグルーピング。Raycast 拡張として
- フロントは Raycast、バックエンドは自分たちで作る
- V0（WorkUnit OS）は凍結。方向としては引き継がない

**今は決めない：**
- 機能特化か体験特化かの定義
- 暫定：**「今は"作業を再開する瞬間"に絞る。そのための機能としてグルーピングを作る。
  範囲は自分たちで使いながら確定させる」**

**降りた特化：**
- 領域特化 — ドメイン知識で勝てない
- 職種特化（エンジニア向け） — AI エージェントに飲まれる
